# T15 — 受限自愈守护策略设计

版本：0.1；状态：G2 前置设计。

---

## 1. 故障分级与自愈触发边界

并非所有异常都需要重启实例，盲目重启将导致测试状态丢失甚至死锁。

| 故障场景 | 判定标准 | 处理策略 | 是否重启实例 |
|---|---|---|---|
| **用户主动停止** | 用户点击停止按钮或发出 Stop API | 正常下发停止并释放配额 | **严禁重启** |
| **投屏窗口关闭** | scrcpy 进程正常或异常退出 | 仅注销投屏会话，释放端口 | **不重启** |
| **任务执行中** | 实例正在接收 APK 安装或 Shell 诊断 | 保持状态，向任务队列报错 | **严禁重启** |
| **非托管实例** | 未被纳入平台管理范围的设备 | 忽略 | **严禁重启** |
| **底层引擎异常退出** | 期望状态为 Ready，但进程意外消失 | 检查预算，受控触发单实例重启 | **受限重启** |

---

## 2. 防重启风暴预算机制 (Anti-Storm Budget)

- **窗口预算**：每个实例在滑动窗口 10 分钟内，最多允许触发 **2 次** 自动重启；
- **强制冷却**：两次自愈重启之间，强制冷却至少 **60 秒**；
- **熔断降级**：当第 3 次故障发生或预算耗尽时，看门狗自动将该实例冻结在 `error` 状态并触发人工报警，不再消耗宿主 CPU 与磁盘 I/O。
