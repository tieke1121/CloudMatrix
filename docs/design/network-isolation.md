版本：0.1；状态：G2 前置设计。

---

## 1. 业务目标与安全边界

在多实例矩阵运行场景中，不同模拟器实例往往需要绑定不同的独立网络出口（例如独立海外节点、专用机房代理或测试网关），防止多账号共用宿主物理 IP 导致关联风控。

### 安全红线
1. **严禁篡改宿主全局网络**：禁止修改宿主 Windows 全局系统代理、禁止注入系统级 LSP 或全局 VPN，避免干扰用户正常开发与办公网络；
2. **Fail-Closed 强制阻断策略**：当实例绑定的代理不可用、超时、鉴权失败或中途崩溃时，网络管道必须立即实施 **Fail-Closed 丢弃**，严格禁止静默回退直连宿主 IP；
3. **凭据安全与零日志泄漏**：代理账号、密码、Token 严禁出现在进程启动命令行、ADB 命令明文、系统环境变量或审计日志中；统一采用安全上下文或内存哈希管理；
4. **协议覆盖边界声明**：必须明确声明 SOCKS5 / HTTP 代理模式下对 TCP、UDP、DNS 污染防范及 IPv6 的支持边界；不支持的协议必须显式 Drop，杜绝流量旁路泄漏。

## 2. 隔离模式与协议支持矩阵

| 模式 | 覆盖协议 (TCP) | 覆盖协议 (UDP) | DNS 解析保护 | IPv6 处理策略 | 泄漏防护能力 (Fail-Closed) |
|---|---|---|---|---|---|
| **SOCKS5 + Remote DNS** | 支持 | 支持 (需服务端支持 UDP ASSOCIATE) | 服务端远端解析，防宿主 DNS 泄漏 | 默认禁用实例内 IPv6 或走代理 | **极高** (代理断线即不可达) |
| **HTTP / HTTPS CONNECT**| 支持 | 不支持 (显式拦截) | 经 HTTP CONNECT 远端解析 | 禁用 IPv6 | **高** (非 HTTP 流量直接丢弃) |
| **Fail-Closed 阻断态** | 拦截 (Drop) | 拦截 (Drop) | 拦截 (Drop) | 拦截 (Drop) | **100% 阻断** (物理隔离无流量) |
| **直连模式 (Direct)**   | 直连宿主网络 | 直连宿主网络 | 本地 DNS 解析 | 本地 IPv6 | 无隔离 (显式提示警告) |

## 3. 架构设计与实现策略

### 3.1 凭据安全生命周期 (`internal/network/credential.go`)

- 代理凭据在内存中以只读句柄持有；
- 传递给底座或 ADB 时，通过 Unix Socket / 本地安全管道或内部回环授权，不通过 `cmd.exe /c` 字符串暴露；
- 审计脱敏：对外部展示时，密码完全掩码为 `******`，用户名仅保留首尾字符。

### 3.2 健康检测与熔断器 (`internal/network/health.go`)

- 启动后台轻量探针，定期向目标代理的出口连通性发探测；
- 探测失败连续 2 次，自动触发熔断，实例网络状态置为 `BLOCKED`，下发路由阻断规则；
- 探测恢复成功连续 2 次，方可解除阻断。

### 3.3 实例内网络策略下发 (`internal/network/isolation.go`)

- 针对 Android 实例，优先通过 `settings put global http_proxy`、私有 APN 或专用网桥转发；
- 默认设置 `iptables -P OUTPUT DROP`（或应用私有链拦截），确保只有目标代理通道被放行。
