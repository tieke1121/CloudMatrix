# T13 — 真正的视频墙与后台资源策略技术设计

版本：0.1；状态：G2 前置设计。

---

## 1. 业务目标与选型对比

多实例矩阵监控（4路/9路/16路视频墙）需要为操作员提供直观、低延迟的实时画面概览与交互能力，同时必须避免多实例同时流式传输导致宿主 CPU/GPU 耗尽。

### 渲染管线路线对比

| 评估维度 | 路线 A：原生 Win32 子窗口嵌入 (`SetParent`) | 路线 B：WebView2 前端解码 (`WebCodecs / Canvas`) | 路线 C：双模混合架构 (CloudMatrix 首选) |
|---|---|---|---|
| **画面渲染延迟** | 极低（15~30 ms），直通 GPU 交换链 | 较低（40~70 ms），经由内存缓冲与浏览器管线 | **网格 50ms / 聚焦 25ms** |
| **UI 组合能力** | 差（存在 Airspace 缺陷，原生窗口遮挡所有 Web 浮层） | 极佳（完美融入 Vue/CSS 布局、弹窗、滤镜与状态遮罩） | **网格融入 Web，聚焦单例弹窗** |
| **高 DPI 与缩放** | 复杂，缩放时易发生窗口错位与撕裂 | 天然支持响应式网格与 DPI 自动缩放 | **高 DPI 自动适配** |
| **RDP / 远程桌面** | 易黑屏或 Direct3D 上下文丢失 | 兼容性高，自动降级为软件绘制 | **断连重连平滑降级** |
| **多路资源开销** | 窗口句柄开销，多进程渲染显存占用大 | 可在后台精准节流至 2~5 fps，内存聚合管理 | **自适应帧率与后台降频** |

**选型决策**：
- **监控矩阵大盘（4/9/16路网格）**：采用路线 B 的 WebSocket / 共享内存流 + 前端 Canvas/WebCodecs 渲染，统一由 Web 布局和分级帧率控制；
- **深度调试与交互（单实例）**：支持一键调用 G1 独立硬件加速投屏窗口，享受零延迟与原生控制体验。

## 2. scrcpy 视频流协议规范与解包

### 2.1 协议帧头结构

scrcpy-server 在视频通道建立后，首先发送 64 字节设备元数据头：
1. **Device Name**：64 字节（以 `0x00` 填充或截断的 UTF-8 字符串）；
2. **Codec ID**：4 字节（如 `0x68323634` 对应 `"h264"`，或 `0x68323635` 对应 `"h265"`）；
3. **Width**：4 字节大端整数（视频宽度）；
4. **Height**：4 字节大端整数（视频高度）。

### 2.2 数据帧包封装

随后流式下发视频数据包：
1. **PTS (Presentation Time Stamp)**：8 字节大端整数（微秒）；
2. **Packet Size**：4 字节大端整数；
3. **Payload**：长度为 `Packet Size` 的 Annex-B NALU 单元字节序列。

### 2.3 异常与断线恢复

- **协议畸形与包校验**：若 `Packet Size` 超过单帧合理上限（如 10 MiB）或小于 0，立即丢弃并标记流异常；
- **自动重连回退**：连接中断后采用指数退避重试（1s, 2s, 4s, 最大 10s），最多重试 3 次；超额标记为 `OFFLINE` 并由看门狗接管；
- **硬解降级**：当 WebView2 宿主环境或客户端上报 WebCodecs 硬件加速失败时，自动降级为软件解码或低帧率 Canvas 绘制。

## 3. 后台资源策略与节流分级

为证明后台降低采集帧率具体节约的系统资源，明确定义以下四种不同级别的资源控制状态：

```text
+-------------------+-------------------------------------------------------------+
| 资源控制状态       | 具体节约资源与执行行为                                        |
+-------------------+-------------------------------------------------------------+
| 1. 全帧率聚焦      | 30~60 fps, 4~8 Mbps。全分辨率投屏，适合当前操作聚焦的设备       |
| 2. 视频墙网格概览  | 10~15 fps, 1~2 Mbps。分辨率等比下采样至 720p/540p，节约 60% 显存|
| 3. 后台/遮挡节流   | 2~5 fps, 0.5 Mbps。实例窗口在非活跃标签页或不可见，节约 85% CPU  |
| 4. 视频流暂停      | 0 fps。断开视频采集管道，模拟器维持运行，节约 100% 解码算力     |
| 5. 实例冻结/暂停   | 模拟器底层暂停执行（freeze），节约 CPU 核心时间与功耗           |
| 6. 真正无头运行   | 模拟器无 GUI 渲染窗口启动，仅保留 ADB 与 ADB Shell 控制通道      |
+-------------------+-------------------------------------------------------------+
```

## 4. 多路自适应清晰度与线程隔离

1. **非 UI 线程解码**：
   - Go 后端每个视频流使用独立 goroutine 处理 Socket 数据解包与帧率丢帧策略；
   - 管道溢出保护：当下游消费者读取速度滞后时，主动丢弃非关键帧（P 帧/B 帧），绝不阻塞其他实例流；
2. **清晰度分级策略**：
   - 4 路并排：单路最大 1080p @ 15fps；
   - 9 路矩阵：单路最大 720p @ 10fps；
   - 16 路网格：单路最大 480p @ 5fps；
3. **高 DPI 与 RDP 断连保护**：
   - 监听窗口 DPI 变更事件，动态调整 Canvas 绘制物理像素比例；
   - 宿主 RDP 会话断开或锁屏时，自动切换至后台节流（2 fps）状态，保护显卡驱动不崩溃。
