# CloudMatrix 验证与发布门槛

日期：2026-11-08。所有结果初始为 NOT_RUN；本文定义如何证明完成，不表示任何平台功能已通过测试。

## 1. 四层证据

1. 单元：纯状态、解析、资源准入、幂等和队列，使用 fake Provider/Runner。
2. 进程集成：真实 Windows 子进程，验证取消、输出背压和归属清理。
3. 设备集成：指定的真实模拟器测试实例，执行启停、安装、投屏和恢复。
4. 部署验收：目标 Windows 服务器/工作站，实测容量、GPU、会话和长稳行为。

下层测试通过不替代上层证据。mock 的成功不能证明厂商 CLI 有此能力；APK 解析不能证明 App 能正常运行；ADB 可用不能证明 Android 就绪。

## 2. 验证记录格式

每次运行保存 run.json、case-results.json、commands.log 和必要指标 CSV；截图/录像仅采集测试界面。日志、环境变量和配置先脱敏。

run.json 必含：run_id、commit（无 Git 时明确 none）、started_at_utc、ended_at_utc、OS build、CPU型号/物理及逻辑核心数、RAM、GPU/驱动、磁盘类型/可用空间、虚拟化状态、模拟器/Android/ADB/scrcpy/应用版本、显示尺寸、实例数、负载脚本版本、是否开启投屏、测量工具。

case-results.json 的每例含 case_id、task_id、status、expected、actual、evidence_paths、exit_code、failure_reason。status 只能为 PASS/FAIL/BLOCKED/NOT_RUN；未运行和被跳过不计入通过率。

样例：

```json
{
  "case_id": "V05-duplicate-start",
  "task_id": "T05",
  "status": "NOT_RUN",
  "expected": "20次并发启动请求只触发一次厂商启动，其他返回同一活跃任务或幂等结果",
  "actual": null,
  "evidence_paths": [],
  "exit_code": null,
  "failure_reason": "尚未实现"
}
```

禁止为了让本例通过把 fake Provider 的调用次数写死为 1；测试应验证实际调度行为。

## 4. 性能测量口径

### 4.1 宿主与实例资源

- 主机 CPU 使用整机逻辑处理器总容量为100%的口径；同时记录物理/逻辑核心数。
- 进程 CPU 由采样间隔中的累计CPU时间差 /（间隔 × 逻辑核心数）计算；不把单核百分比与整机百分比混用。
- 实例归属需记录模拟器主进程、子进程和相关服务的归属证据；共享服务单列，不能重复分摊后声称精确单实例成本。
- 内存至少同时记录 Working Set、Private Bytes 和宿主 Commit/可用内存；GPU显存及解码占用另列。
- 区分空闲、启动峰值、播放负载、安装负载、全部视频墙显示和后台隐藏。
- 每档预热10分钟、采样30分钟；采样间隔1秒。只排除明确记录的预热区间，失败时段不能从结果删除。

### 4.2 交互与同步延迟

- 视频端到端延迟：测试 App 渲染带时标画面，到宿主实际显示该画面的差值；说明源/宿主时钟映射误差。
- 输入到反馈：从宿主注入动作到测试 App 状态变化实际出现在宿主画面的差值；不能拿 socket 写入耗时冒充此值。
- 同步发送偏差：同一事件各目标发送时间差；同步执行偏差：测试 App 实际收到/处理事件的时间差。二者分开报告。
- 每个条件至少200次有效事件，记录 P50/P95/P99、失败率及测量误差；跨宿主使用时钟校准或共同录像时间基准。
- 原文50ms交互、10ms同步保留为优化目标，不作为未校准环境下的硬性承诺。正式 SLO 必须在目标部署配置验证后冻结。

### 4.3 容量等级

定义 CM-1、CM-5、CM-10、CM-20 等测试等级，仅表示对应固定负载下验证过的并发数量，不表示所有 App 的通用容量。

达到下一档需同时满足：无内存耗尽/持续换页恶化、磁盘余量充足、命令成功率符合已冻结SLO、UI仍可操作、无失控进程增长。不能仅凭“窗口都打开了”判定容量通过。

初始保护策略：可用物理内存低于 max(总内存15%, 2GiB) 时拒绝新启动；磁盘可用低于 max(目标卷容量10%, 10GiB) 时拒绝新建/克隆；阈值可配置并记录。保护策略是起点，不是容量估算算法。已运行任务不得因触发准入阈值而被无差别终止。

## 5. 故障注入

每个故障只作用于测试资产，并在运行前记录回收方法：

- 工具路径失效/不支持版本：拒绝运行并指出工具；不自动下载替代版本覆盖。
- 厂商 CLI 挂起：有界超时，状态unknown/error，任务可追踪。
- ADB端口变更/断线：重新发现准确serial；不误连实体手机或另一实例。
- 数据盘满：用隔离测试卷/目录配额模拟，不填满用户真实系统盘。
- 数据库锁与迁移中断：保持可恢复；重启不清空实例配置。
- scrcpy退出：释放会话，实例继续运行；重新打开可恢复。
- 桌面进程异常退出：重新发现实例，已运行任务标interrupted并核对真实结果。
- 宿主重启/RDP断连/休眠：记录模拟器是否继续可用、GPU变化和恢复时间，不默认支持。
- 远程响应丢失：相同幂等键查询既有结果，不重复执行安装/克隆。
- 代理服务断开：按声明验证阻断，不能静默回退直连后仍显示隔离正常。

## 6. 可靠性与泄漏门槛

MVP：2小时固定负载，启停10轮、开关投屏30轮、三目标混合任务至少5轮；无宿主崩溃、无错误目标执行、无无法解释的任务丢失。

生产候选：目标容量168小时，至少记录每小时趋势与全部恢复事件。完成50次开关投屏后，稳定期进程/句柄计数回到基线容差范围；Private Bytes较预热基线增长超过 max(10%, 100MiB) 或持续单调增长时必须调查，不能简单标成缓存正常。容差与采样方法随报告说明。

业务数据隔离：两个冷克隆实例写入不同的自有测试App标记，重启后只读到各自标记；一个实例清理数据不影响另一个。该证据仅证明所测存储隔离，不能推出第三方平台不会关联账号。

## 7. 发布判定

- G0：V00通过，工具版本/能力明确。
- G1：V01~V11通过；所有阻塞缺陷解决，明确只支持单宿主和独立投屏窗口。
- G2：所发布的V12~V15通过，实时视频墙和同步分别验收；未实现功能在UI禁用或不展示。
- G3：V16~V18通过，目标服务器兼容矩阵、容量等级、升级恢复步骤齐全。
- 任一数据串扰、误操作其他实例、凭据泄漏、无法回滚的损坏、伪造任务成功为发布阻塞项。

首次开发交付不要求开发电脑完成全部服务器长稳测试，但必须清楚标记这些验证尚未完成；没有目标服务器的测试不能写为生产就绪。
